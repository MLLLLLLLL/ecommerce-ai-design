# 画布与工作流仓库入口改造修复文档

## 修复范围

- 侧边栏点击「无限画布」「工作流」后的进入方式。
- 画布项目与工作流项目的持久化与多项目管理。

## 目标交互

- 点击侧边栏「无限画布」→ 先进入**画布仓库**列表页，展示全部画布项目（卡片：缩略图、名称、更新时间）；点击某个项目卡片才进入该项目对应的画布编辑器。
- 点击侧边栏「工作流」→ 先进入**工作流仓库**列表页；点击某个项目卡片才进入该项目对应的工作流编辑器。
- 仓库页提供「新建 / 重命名 / 删除 / 导入 JSON」入口；编辑器内保存写回仓库，不再依赖本地下载文件。

## 问题

### 现象

侧边栏点击「无限画布」「工作流」后直接进入唯一的编辑器页面。所有画布/工作流共用这一个实例，内容只存在于页面内存中：

- 刷新页面、切换菜单后，未手动「保存」的内容全部丢失。
- 「保存」实际是下载一个 JSON 文件到本地，「加载」是上传 JSON 文件，项目之间无法在产品内管理和切换。
- 无法做到「点击仓库中的项目，进入既定的画布/工作流」。

### 原因

1. 路由是单层直达：侧边栏 `href` 直接指向编辑器页，没有列表层。
   - `src/components/shared/Sidebar.tsx:20-21`：`{ name: '无限画布', href: '/canvas' }`、`{ name: '工作流', href: '/workflow' }`。
2. 编辑器状态全部在内存，持久化只有文件导入导出：
   - 画布 `src/app/(dashboard)/canvas/page.tsx:376-446`（`handleSave`/`handleLoad`，version 2 复合格式：`{ version, fabric, nodes, connections, viewport }`）。
   - 工作流 `src/app/(dashboard)/workflow/page.tsx:230-272`（`{ nodes, edges }`）。
3. 数据库已具备承载能力但未接线：
   - `WorkflowTemplate` 表在 init 迁移中已建（`prisma/migrations/20260811123535_init/migration.sql:95`，`definition Json` 字段正好存 `{ nodes, edges }`），但 `src` 中零引用，`src/app/api/workflow/` 下没有任何 route。
   - 画布项目没有任何对应的数据模型。

## 修复方案

### 总体思路

加一层「仓库」列表页，编辑器下沉到动态路由；内容持久化到数据库。侧边栏 `href` 不变（`/canvas`、`/workflow` 变为仓库页），`Sidebar.tsx` 的 `pathname.startsWith(item.href)` 高亮逻辑对 `/canvas/xxx` 子路由天然兼容，无需改动。

### 一、路由结构调整（App Router，`(dashboard)` 为路由组不影响 URL）

| 页面 | 现状 | 改造后 |
| --- | --- | --- |
| 画布仓库 | 无 | `src/app/(dashboard)/canvas/page.tsx`（新建，列表页） |
| 画布编辑器 | `src/app/(dashboard)/canvas/page.tsx` | 迁移至 `src/app/(dashboard)/canvas/[id]/page.tsx` |
| 工作流仓库 | 无 | `src/app/(dashboard)/workflow/page.tsx`（新建，列表页） |
| 工作流编辑器 | `src/app/(dashboard)/workflow/page.tsx` | 迁移至 `src/app/(dashboard)/workflow/[id]/page.tsx` |

注意：本项目 Next.js 版本与训练认知有 breaking changes（见根 `AGENTS.md`），实现动态路由前先查 `node_modules/next/dist/docs/`。两个编辑器页均为 `'use client'` 组件，客户端内用 `useParams()` 取 `id` 即可，规避新版 `params` Promise 化的差异。

### 二、数据模型

1. 新增画布项目模型（`prisma/schema.prisma`），不复用现有 `Project`（其语义是资源/工作流的分组容器）：

```prisma
model CanvasProject {
  id         String   @id @default(uuid())
  userId     String
  user       User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  name       String
  thumbnail  String?  // 导出 PNG 的 dataURL 或 /api/files 路径，用于仓库卡片
  definition Json     // 现有 version 2 复合格式：{ version, fabric, nodes, connections, viewport }

  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt

  @@index([userId, updatedAt])
}
```

`User` 模型上补 `canvasProjects CanvasProject[]` 关系字段。

2. 工作流直接复用已有 `WorkflowTemplate` 表（`name` / `description` / `definition Json` / `updatedAt` 已齐全），不改表结构。

3. 执行 `npx prisma migrate dev` 生成迁移；`definition` 落库内容与现有 JSON 文件格式完全一致，旧文件可无损导入。

### 三、API 设计

遵循现有 API 约定（参考 `src/app/api/folders/route.ts`：`NextRequest/NextResponse`、`{ success, ... }` 响应、默认用户 `local@user.com` 兜底创建）。

画布项目（新建 `src/app/api/canvas-projects/route.ts` 与 `[id]/route.ts`）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/canvas-projects` | 列表，按 `updatedAt desc`，**不返回** `definition` 大字段，只回 meta + `thumbnail` |
| POST | `/api/canvas-projects` | 新建 `{ name }`，`definition` 落一份空画布初始 JSON，返回完整记录 |
| GET | `/api/canvas-projects/[id]` | 详情，含 `definition`，进入编辑器时调用 |
| PATCH | `/api/canvas-projects/[id]` | 保存 `{ name?, definition?, thumbnail? }` |
| DELETE | `/api/canvas-projects/[id]` | 删除 |

工作流项目（新建 `src/app/api/workflows/route.ts` 与 `[id]/route.ts`）：同上，落 `WorkflowTemplate` 表；`POST` 默认 `{ nodes: [], edges: [] }`。

### 四、仓库列表页

参照资源库页（`src/app/(dashboard)/assets/page.tsx`）的既有模式：卡片网格 + 搜索 + 删除确认 + loading 态，不引入新组件库。

- 卡片内容：画布显示 `thumbnail` 预览图；工作流显示名称 + 节点数（`definition.nodes.length`）+ 更新时间。
- 顶部操作：「新建画布 / 新建工作流」（POST 成功后 `router.push` 进编辑器）、「导入 JSON」（读本地旧格式文件 → POST 创建项目）。
- 卡片操作：点击进入编辑器；更多菜单里放重命名（PATCH）与删除（DELETE）。
- 空态：引导文案 + 新建按钮。

### 五、编辑器改造（迁移后的 `[id]/page.tsx`）

1. 进入时用 `useParams()` 取 `id`，调 `GET /api/.../[id]` 加载：
   - 画布：复用现有 `handleLoad` 中 version 2 分支的恢复逻辑（`canvas/page.tsx:411-428`），抽成 `loadDefinition(payload)` 供初始加载与文件导入共用。
   - 工作流：复用 `handleLoad` 的 setNodes/setEdges 恢复逻辑（`workflow/page.tsx:252-267`）。
   - 加载完成后再初始化历史栈（画布调一次 `resetProjectHistory()`）。
2. 「保存」按钮改为 `PATCH` 写库（画布保存时顺手用 `canvasManager.exportToImage('png', 0.3)` 生成缩略图一并提交）；原下载/上传 JSON 的按钮保留为「导出 / 导入」。
3. 自动保存：监听内容变化做防抖（建议 2s）`PATCH`，与现有历史记录节流思路一致；失败时 toast 提示，避免静默丢数据。
4. 顶部工具栏加「返回仓库」链接（`next/link` 指回 `/canvas` 或 `/workflow`）。
5. 加载失败（id 不存在）时 toast 并跳回仓库页。

### 六、画布 ⇄ 工作流联动适配

`src/stores/workflowBridge.ts` 的队列机制不变，但跳转落点从「唯一编辑器」变成了「仓库页」，需要补一层引导：

- 工作流「送入画布」后（`workflow/[id]/page.tsx` 的 `handleSendToCanvas`），toast 文案改为引导去画布仓库；画布仓库页检测 `pendingCanvasImages` 非空时显示横幅「有 N 张工作流图片待接收」，用户点击目标画布项目进入后由编辑器现有逻辑消费（`canvas/[id]/page.tsx:337-351`）。
- 画布「送入工作流」同理，工作流仓库页显示待接收横幅。
- 不改动 bridge store 结构，只在两个仓库页各加一段消费提示逻辑。

### 七、兼容性

- 旧的本地下载 JSON 文件：通过仓库页「导入 JSON」创建为新项目，格式不变（画布 version 2 / 工作流 `{nodes, edges}`）。
- 画布旧版纯 fabric JSON（无 `version` 字段）：沿用现有兼容分支（`canvas/page.tsx:429-436`）。
- 侧边栏、Dashboard 布局、其余页面零改动。

## 验收标准

- 点击侧边栏「无限画布」首先进入画布仓库列表页，展示已保存的画布项目卡片；点击项目卡片进入 `/canvas/[id]` 编辑器，内容与前次保存一致。
- 点击侧边栏「工作流」首先进入工作流仓库列表页；点击项目卡片进入 `/workflow/[id]` 编辑器，节点与连线恢复完整。
- 编辑器内「保存」后刷新页面、退出重进，内容不丢失；自动保存生效（停止操作约 2s 后写库）。
- 仓库页可新建、重命名、删除项目；可导入旧版本地 JSON 文件生成新项目。
- 编辑期间侧边栏「无限画布 / 工作流」保持高亮；编辑器可一键返回仓库。
- 工作流「送入画布」、画布「送入工作流」流程在仓库模式下可用：仓库页出现待接收提示，进入目标项目后图片正确落位。
- `npx prisma migrate dev` 迁移成功，`npx tsc --noEmit`（或项目既有 lint/build 检查）通过。
