# 营销助手2交互设计文档 V3

## 1. 文档信息

- **文档状态**：V3 交互方案，待评审
- **适用入口**：`/marketing2`
- **基础需求**：`设计1.md`
- **前序版本**：`营销助手2_交互设计文档V2.md`
- **核心变化**：由“五张并列工作流卡片”调整为“一张主流程卡片 + 五步连续向导”。

## 2. V3 核心决策

1. 营销助手2首页只保留一张核心业务卡片，名称为“主图详情页全自动生成”。
2. 原“底图净化、视觉策划与提示词、批量生图、质检与返修”不再作为并列入口，全部成为主流程内部步骤。
3. 一个任务贯穿五步，产品图、用户参数、模型选择、提示词、生成图片和质检结果持续传递。
4. 第一步“准备产品图”和第二步“可选精修成干净底图”属于两个逻辑步骤，但在同一个界面中完成。
5. 用户关闭精修开关时，第二步记为“已跳过”，原始产品图直接进入第三步。
6. 用户开启精修开关时，只能选择模型，不能修改系统预设精修提示词。
7. 第三步生成完整主图和详情页提示词，第四步逐张生图，第五步逐张质检并局部返修。
8. 每个需要模型的步骤均从“设置”引用模型；存在多个模型时允许自由选择。
9. 上游数据修改后，下游结果不会静默继续使用，必须显示影响范围并要求重新确认或重新生成。
10. 每个涉及提示词生成、图片生成或图片返修的界面，都必须在当前页面显示对应的文本模型或图片模型下拉框；各页面的模型选择独立保存，不自动继承、联动或覆盖其他页面。
11. 所有模型下拉框只引用“设置”中已保存的服务端模型；营销助手2不读取浏览器本地图片服务配置，也不允许临时填写模型名称、地址或密钥。

## 3. 产品目标

营销助手2面向希望从产品素材直接获得整套电商主图和详情页的用户。用户不需要理解独立工具之间的关系，只需要沿着一个连续流程完成：

```text
1. 准备产品图
   ↓
2. 可选精修干净底图
   ↓
3. 生成整套主图和详情页提示词
   ↓
4. 逐张生成主图和详情页
   ↓
5. 质检、返修和复检
```

最终形成“一次输入、逐步确认、失败局部处理、完整资产可追溯”的电商视觉生产闭环。

## 4. 营销助手2首页

### 4.1 页面组成

- 页面标题：营销助手2。
- 辅助说明：按步骤完成产品图准备、视觉策划、生图和质量验收。
- 右上角保留“返回旧版营销助手”。
- 顶部保留“最近任务”。
- 主区域只显示一张“主图详情页全自动生成”卡片。

### 4.2 唯一卡片内容

**卡片名称**：主图详情页全自动生成

**卡片摘要**：

```text
输入：至少 1 张同一产品图片、产品基本信息
输出：干净底图、主图提示词、详情页提示词、营销图片、质检结果
步骤：准备产品图 → 可选底图精修 → 提示词策划 → 逐张生图 → 质检返修
```

### 4.3 卡片状态

- **可开始**：当前没有未完成任务，基础模型能力满足。
- **继续任务**：存在草稿、执行中或等待确认的任务；按钮优先显示“继续任务”。
- **部分能力缺失**：允许进入任务，但在对应步骤执行前提示缺少的模型能力。
- **需要配置模型**：完成主流程所需的关键模型均不可用，主操作变为“配置模型”。

底图精修属于可选步骤，因此仅缺少图片编辑模型时，不阻止用户进入工作流或跳过第二步。

### 4.4 最近任务

最近任务显示：任务名称、当前步骤、状态和更新时间。点击后恢复到任务当前步骤，不能创建重复任务。

状态示例：

- 草稿：第一步
- 待确认：底图精修
- 生成中：第 4/12 张
- 待返修：2 张不合格
- 已完成

## 5. 工作流页面整体结构

### 5.1 顶部区域

- 返回营销助手2。
- 任务名称，默认使用“产品名 + 主图详情页”。
- 保存状态：未保存、保存中、已保存、保存失败。
- 任务状态：草稿、执行中、待确认、部分失败、已完成。
- 当前任务使用的产品缩略图。

### 5.2 五步进度条

```text
① 准备产品图
② 底图精修（可选）
③ 提示词策划
④ 逐张生图
⑤ 质检返修
```

步骤状态统一为：

- 未开始
- 处理中
- 待确认
- 已完成
- 失败
- 已跳过

用户可以查看已完成步骤，但不能绕过未满足的前置条件直接执行后续步骤。

### 5.3 主操作区

- 中间显示当前步骤内容。
- 页面底部固定显示“上一步”和主操作按钮。
- 主操作按钮按状态显示“保存并继续”“开始精修”“生成提示词”“生成下一张”“进入质检”“完成任务”等。
- 切换页面、刷新浏览器或返回首页后，任务上下文必须保留。

## 6. 第一步与第二步：产品图和可选精修

第一步和第二步在同一个界面中完成，但进度条仍显示两个逻辑步骤。

### 6.1 产品图片输入

- 支持上传 1-5 张图片。
- 支持从资源库选择。
- 支持拖拽排序、删除和替换。
- 第一张图片默认为主参考图，用户可以重新指定。
- 其余图片作为同一产品不同视角的补充参考。
- 不允许把多图解释为多个 SKU、多个款式或多个产品。

图片区域显示：

- 主参考图标记。
- 图片上传/读取状态。
- 格式和大小错误。
- 多图外观冲突提醒。

### 6.2 “精修成干净底图”开关

产品图区下方提供一个可选开关：

```text
精修成干净底图  [关闭/开启]
```

#### 关闭时

- 不展示精修模型选择器和精修结果区。
- 第二步状态记为“已跳过”。
- 原始主参考图与补充视角图进入第三步。
- 主操作按钮显示“下一步：生成提示词”。

#### 开启时

- 在当前页面展示“底图精修图片模型”下拉框。
- 只展示设置中已启用、实测通过并支持图片编辑和参考图的模型。
- 该下拉框只控制第二步底图精修，不影响第三步、第四步和第五步的模型选择。
- 展示“开始精修”按钮。
- 精修系统提示词不可编辑。
- 可以提供“查看精修规则”的只读入口。
- 精修中禁止修改主参考图和模型。

### 6.3 多图精修规则

- 主参考图决定输出底图的主要角度和构图。
- 其他视角只用于补充识别轮廓、结构、比例、材质、包装和可见细节。
- 首期每次精修输出 1 张干净底图。
- 重新精修产生新版本，不覆盖上一版。

### 6.4 精修结果确认

结果区同时显示原始主参考图和精修底图，支持：

- 接受并继续。
- 重新生成。
- 更换模型后重新生成。
- 放弃精修并使用原图。

只有用户接受精修结果后，第三步才优先使用精修底图。未接受或放弃时继续使用原图。

### 6.5 固定精修提示词

```text
请把我上传的产品图精修成适合后续电商主图和详情页生图参考的干净产品底图。

要求：
1. 严格保持产品原本的品类、轮廓、比例、结构、颜色、材质、表面工艺、Logo、包装和可见细节不变。
2. 背景处理为干净纯白、浅灰白或极简中性底色，去除杂物、水印、脏污、过曝、阴影混乱和无关元素。
3. 不要新增原图没有的按钮、接口、配件、包装、文字、纹理、装饰、功能结构或品牌元素。
4. 如果上传了多张同产品不同视角图，只把它们作为同一产品外观补充参考，不要合成不存在的新结构。
5. 输出主体完整、边缘清晰、光影自然、真实可信、适合继续用于电商生图参考的产品底图。
```

## 7. 第三步：生成整套提示词

### 7.1 输入图片路由

- 第二步已接受精修结果：精修底图作为主参考，原始多视角图继续作为补充参考。
- 第二步关闭、跳过或放弃精修：原始主参考图作为主图，其余图片作为补充参考。
- 所有图片仍属于同一商品任务。

### 7.2 用户输入区

界面使用结构化表单，不要求普通用户直接填写 YAML。

字段包括：

- 平台
- 输出语言
- 主图数量
- 详情页数量
- 主图比例
- 详情页比例
- 产品名称
- 品牌名
- 核心卖点
- 产品参数
- 目标人群
- 使用场景
- 价格带/定位
- 设计风格
- 禁止出现
- 其他要求

主图数量和详情页数量支持：

- 依产品特性生成
- 用户指定数量

数量边界：

- 主图手动指定范围为 1-10 张。
- 详情页手动指定范围为 1-20 页。
- 主图和详情页合计不超过 30 个生成项。
- 选择“依产品特性生成”时，由模型在上述范围内决定数量，不能突破服务端上限。

主图比例未填写时默认 `1:1`；详情页比例未填写时默认 `3:4`。

### 7.3 用户输入优先级

1. 用户填写了具体内容：必须优先使用。
2. 字段为空或选择“依产品特性生成”：根据产品图、品类、购买决策和转化逻辑生成。
3. 图片可见信息与用户参数冲突：保留真实外观，冲突参数标记为“待核对”。
4. 无法确认的数字、认证、成分、功效、型号、销量和价格：不得编造，只能使用占位符。

### 7.4 模型选择

第三步包含两个模型角色：

- **产品视觉识别模型**：需要视觉输入和结构化输出能力。
- **策划与提示词模型**：需要稳定中文创作和结构化输出能力。

当前页面必须分别显示两个文本模型下拉框：

```text
产品视觉识别模型  [选择文本模型]
提示词生成模型    [选择文本模型]
```

- 两个下拉框分别控制产品识别调用和提示词生成调用。
- 两个下拉框允许选择同一个模型，但系统不自动进行跟随或同步。
- 第三步的选择只在第三步生效，不继承第二步图片模型，也不作为第四步图片模型的默认值。
- 用户重新进入第三步时恢复第三步上次保存的两个模型选择。

### 7.5 系统策划规则

系统固定执行以下逻辑，普通用户不可编辑：

1. 判断单图或同一产品多视角图。
2. 综合识别品类、轮廓、结构、颜色、材质、表面工艺、包装、Logo 和可见文字。
3. 生成全局“产品外观锁定描述”。
4. 区分可确认信息、合理推断和不可确认信息。
5. 根据产品复杂度和转化链路确定自动数量，不使用固定 5、6、8 页模板。
6. 缺少参数时生成“待补充参数位”等占位符。
7. 规划主图和详情页的顺序、职责、信息层级和统一视觉系统。
8. 每张主图和每页详情页输出可直接用于生图的中文提示词。
9. 每条提示词必须以“以用户上传的产品图作为唯一外观参考，严格复刻产品原貌”开头。
10. 每条提示词必须复用全局产品外观锁定描述。
11. 不输出分析过程，只输出最终可用内容。

### 7.6 主图策划约束

- 服务点击率、商品识别和卖点转化。
- 每张主图职责不同，不重复凑数。
- 产品主体建议占画面 45%-70%。
- 文字短句化、模块化，不使用乱码、伪字和过密小字。
- 可根据产品选择白底首图、场景图、卖点图、细节图、结构图、参数图、包装图等。
- 产品不具备的信息不强行生成对应页面。

### 7.7 详情页策划约束

- 每页具有独立职责和阅读路径。
- 产品主体建议占画面 35%-55%。
- 每页形成 3-5 个信息区块。
- 使用网格、分栏、标注线、参数卡片、底部信息条等模块化排版。
- 不为了固定页数重复页面。
- 所有页面保持统一的色彩、字体气质、图标风格、卡片样式和光影语言。

### 7.8 输出结果界面

结果分为三个区域：

1. 产品外观锁定描述。
2. 主图生图提示词列表。
3. 详情页生图提示词列表。

每条结果展示：序号、关键词、完整中文提示词、比例和页面职责。支持编辑、复制、排序、删除和重新生成单条。

输出格式：

```text
产品外观锁定描述：
【产品品类、轮廓、结构、颜色、材质、表面工艺、Logo/包装/可见细节】

# 主图生图提示词

主图一：关键词
生图提示词：...

# 详情页生图提示词

页面一：关键词
生图提示词：...
```

用户确认提示词后进入第四步。未确认时，第四步不能开始生成。

## 8. 第四步：逐张生成图片

### 8.1 数据来源

第四步自动接收：

- 已确认的产品外观锁定描述。
- 已确认的主图和详情页提示词。
- 精修底图或原始主参考图。
- 原始补充视角图。
- 每张图的比例和页面职责。

### 8.2 页面结构

左侧显示待生成清单，右侧显示当前图片的提示词、模型、参考图和生成结果。

每个生成项包含：

- 类型：主图或详情页。
- 序号和关键词。
- 页面职责。
- 比例。
- 提示词只读预览。
- 图片模型。
- 生成状态。
- 最新结果和历史版本。

### 8.3 模型选择

- 第四步页面必须显示图片模型下拉框，明确当前生成动作将调用哪个图片模型。
- 每张主图和每页详情图都是独立生成项，每个生成项都保存自己的图片模型选择。
- 切换到另一张主图或详情页时，显示该生成项自己的模型下拉框和值。
- 可以提供“批量设置模型”操作，将同一个模型一次应用到多个尚未生成的项目，但应用后每项仍保存独立模型 ID。
- 修改某一项的图片模型不能影响已经生成或其他尚未生成的项目。
- 只展示支持图片生成和参考图输入的设置模型。
- 模型在任务中失效时保留历史模型快照，但新生成必须重新选择。

### 8.4 生成方式

- 默认每次只生成 1 张。
- 页面提供并发数量选择，范围为 1-5，默认值为 1。
- 提供“批量生成”，系统根据并发值同时处理多个生成项，但每项仍独立展示模型、进度和结果。
- 并发值只控制当前任务第四步，不影响其他任务和其他页面。
- 实际并发数还必须服从模型服务和系统全局并发上限；资源不足时自动排队，不丢弃任务。
- 当前项完成后可以接受、重新生成或切换模型再生成。
- 主图使用用户设置比例，默认 `1:1`。
- 详情页使用用户设置比例，默认 `3:4`。
- 产品参考强度优先调高，风格参考强度适中。
- 支持“无文字版”选项，用于降低图片中文字错误。

### 8.5 步骤完成门槛

- 所有计划项必须达到“已接受”或由用户填写原因后“已跳过”。
- 生成失败的单项可以重试，不影响其他图片。
- 用户可以暂停并稍后继续。
- 点击“下一步：质检验收”后进入第五步。

## 9. 第五步：质检、返修和复检

### 9.1 质检输入

第五步接收第四步所有已接受图片，并保留原提示词、参考图、模型和版本关系。

### 9.2 质检模型

- 第五步页面分别显示“质检文本模型”和“返修图片模型”两个下拉框。
- 每张待质检图片独立保存质检文本模型选择。
- 每次返修独立保存返修图片模型选择。
- 质检文本模型需要视觉输入和结构化输出能力。
- 返修图片模型需要图片编辑和参考图能力。
- 两个下拉框只控制当前图片的质检和返修，不继承第四步生图模型，也不影响其他图片。

### 9.3 十项检查

1. 产品品类、颜色、结构、比例、材质、Logo 和包装一致性。
2. 多图视角仍属于同一产品，没有混成新款式或新结构。
3. 主图商品识别是否清晰，是否具备点击理由。
4. 详情页职责是否清晰，页面之间是否重复。
5. 卖点是否可信，是否存在虚构功能、认证、功效、销量或价格。
6. 参数是否真实，信息不足时是否使用占位符。
7. 中文文字是否清晰，无乱码、错别字和排版错误。
8. 整套视觉是否统一，同时每页构图和信息重点不同。
9. 背景、道具和人物是否服务产品，没有喧宾夺主。
10. 比例、留白、安全边距和主体占比是否适合上架。

每项状态为：通过、警告、不通过、人工确认。

### 9.4 返修交互

不通过的图片展示问题类型和建议返修动作：

- 外观跑品
- 文字错误
- 信息虚构
- 设计普通

用户选择问题类型和返修模型后执行返修。返修提示词为系统固定模板，只读展示，不允许直接修改。

每次返修都创建独立返修请求，状态为：

```text
待执行 -> 排队中 -> 返修中 -> 待确认 -> 已接受
                       └-> 失败 -> 重试
```

返修请求创建后保留所选问题类型、返修模型、原始图片版本和创建时间。切换到其他图片不会丢失该请求。

返修结果：

- 创建新的图片版本。
- 原图继续保留。
- 自动进入复检。
- 复检仍不合格时可以继续返修或人工确认。

### 9.5 完成门槛

- 所有图片质检通过；或
- 警告项已由用户确认；或
- 不通过项已经返修通过；或
- 用户填写原因后进行人工确认。

满足后显示“完成任务”，生成最终资产清单、提示词包和质检报告。

## 10. 固定返修模板

### 10.1 外观跑品

```text
请基于上一版重新生成，但必须严格回到用户上传产品图的真实外观。保持产品品类、轮廓、比例、结构、颜色、材质、Logo、包装和可见细节不变。删除上一版中新增的错误部件、错误纹理、错误配件、错误文字或不存在的结构。可以优化背景、光影和版式，但不能改变产品本身。
```

### 10.2 文字错误

```text
请基于上一版重新生成，重点修正图中文字。所有中文必须清晰、规范、可读，无乱码、无错别字、无伪字。保留原来的构图、产品外观、色彩风格和信息层级，只优化文字排版、字距、行距、对齐关系和可读性。
```

### 10.3 信息虚构

```text
请基于上一版重新生成，删除所有无法从产品图或用户输入区确认的具体参数、认证、功效、销量、价格、型号和绝对化承诺。信息不足的位置统一改为“待补充参数位”“待补充规格位”“以实物信息为准”等占位表达。画面信息密度可以保留，但不能靠虚构信息填充。
```

### 10.4 设计普通

```text
请基于上一版提升商业设计完成度。不要只做产品居中、单色背景和一行标题。保持产品外观不变，重新增强版式层级、信息模块、背景材质、光影结构、细节标注、卖点标签、底部信息条和整体品牌感。画面要像成熟电商设计师完成的主图/详情页视觉稿，文字清晰可读，商品识别度更强。
```

## 11. 设置模型引用规则

| 逻辑步骤 | 模型角色 | 必需能力 |
|---|---|---|
| 第一步 | 无 | 无 |
| 第二步 | 底图精修模型 | 图片编辑、参考图输入 |
| 第三步 | 产品视觉识别模型 | 视觉输入、结构化输出 |
| 第三步 | 策划与提示词模型 | 中文文本生成、结构化输出 |
| 第四步 | 图片生成模型 | 图片生成、参考图输入 |
| 第五步 | 质检模型 | 视觉输入、结构化输出 |
| 第五步 | 返修模型 | 图片编辑、参考图输入 |

### 11.1 页面模型下拉框

| 界面 | 必须显示的下拉框 | 控制的调用 | 保存范围 |
|---|---|---|---|
| 第一步：准备产品图 | 无 | 不调用模型 | 无 |
| 第二步：底图精修 | 底图精修图片模型 | 生成干净底图 | 当前精修步骤 |
| 第三步：提示词策划 | 产品视觉识别文本模型 | 识别图片与产品信息 | 当前第三步任务 |
| 第三步：提示词策划 | 提示词生成文本模型 | 生成整套主图与详情页提示词 | 当前第三步任务 |
| 第四步：逐张生图 | 图片生成模型 | 生成当前主图或详情页 | 当前单张生成项 |
| 第五步：质检返修 | 质检文本模型 | 质检当前图片 | 当前单张质检项 |
| 第五步：质检返修 | 返修图片模型 | 返修当前图片 | 当前单次返修任务 |

### 11.2 独立保存规则

1. 每个下拉框都直接读取设置中的模型列表。
2. 页面 A 修改模型，不得改变页面 B 已保存的模型。
3. 第四步每张主图和每页详情图分别保存模型 ID 和模型快照。
4. 第五步每张图片分别保存质检模型；每次返修分别保存返修模型。
5. 页面刷新或返回上一步后，恢复该页面或该生成项上次保存的模型。
6. 允许用户使用“批量设置模型”提高效率，但批量设置只是批量写入独立选择，不建立持续联动关系。
7. 模型被停用或删除后，历史模型快照继续显示；再次执行时必须在当前页面重新选择。

### 11.3 通用选择规则

1. 设置页是模型配置唯一来源。
2. 只展示已启用、实测通过、能力匹配的模型。
3. 下拉框应显示配置名称、实际模型名和能力标签。
4. 页面可以预选该角色的推荐模型，但用户确认后只保存为本页独立选择。
5. 所有生成按钮旁必须能明确看到本次将调用的模型。
6. 未选择模型或模型能力不匹配时，当前生成按钮不可执行，并提供前往设置入口。
7. API Key、Base URL 和完整模型配置不进入任务页面。
8. 选择模型时只保存模型 ID；真正执行前由服务端按当前用户重新读取设置模型并校验能力。

## 12. 上下游修改与失效规则

为防止旧结果错误复用，上游修改后必须标记受影响的下游结果：

| 修改内容 | 受影响结果 |
|---|---|
| 替换主参考图 | 精修底图、提示词、生成图片、质检结果全部失效 |
| 增删补充视角图 | 视觉识别、提示词、生成图片和质检结果失效 |
| 开启/关闭底图精修 | 提示词、生成图片和质检结果失效 |
| 修改产品参数或卖点 | 提示词、生成图片和质检结果失效 |
| 修改某一条提示词 | 对应图片及其质检结果失效 |
| 重新生成某张图片 | 该图片原质检结果失效 |

失效不代表删除：历史版本继续保留，但不能作为当前有效结果进入下一步。

第四步需要为每条提示词维护独立的当前图片状态：当前有效图片、提示词版本、模型、图片版本和是否失效。重新生成只替换“当前有效图片”引用，不删除任何历史 Asset。

## 13. 文件命名与资产关系

```text
产品名_主图_01_关键词.png
产品名_主图_02_关键词.png
产品名_详情页_01_关键词.png
产品名_详情页_02_关键词.png
```

产品名不确定时使用保守品类名。文件名中的非法字符需要自动清理，重名时追加任务短 ID 或版本号。

资产需要记录：任务、步骤、产品参考图、提示词、模型快照、原始版本、返修版本和质检结果。

## 14. 异常与恢复

- 上传部分失败：保留成功图片，失败项可重传。
- 模型未配置：保持当前输入，提供前往设置入口。
- 模型失效：不清空历史结果，新执行前重新选择。
- 上游超时或限流：当前步骤保留，可单项重试。
- 生图部分失败：其他成功图片继续保留。
- 页面刷新或关闭：恢复到任务当前步骤。
- 重复点击：不得生成重复任务或重复图片。
- 返回上一步：所有已填写内容和历史版本保留。

## 15. 历史任务兼容

- V3 新任务使用单卡片五步向导。
- V2 已创建任务继续使用原 V2 界面打开，允许继续执行、查看和导出。
- V2 的四张独立工作流卡片不再允许新建，但历史任务不会被删除。
- 最近任务需要标记任务版本，并自动进入对应版本的运行界面。

## 16. 响应式交互

- 桌面端：左侧步骤栏、中间内容、右侧模型和任务摘要。
- 平板端：步骤栏顶部横向展示，内容与模型区上下排列。
- 移动端：五步进度横向滚动，图片预览单列，底部操作栏固定。
- 长提示词使用折叠和独立滚动区，不撑破页面。
- 图片、文字、按钮和状态标签不得重叠。

## 17. 最终合格标准

1. 任意一张图片单独看都能识别产品。
2. 整套图片形成清晰购买决策路径。
3. 产品外观稳定，不跑品、不换款、不改色、不改结构。
4. 卖点可信，不依赖虚构参数。
5. 可推断内容合理生成，不可确认内容使用占位符。
6. 主图负责吸引点击，详情页负责解释价值和建立信任。
7. 视觉风格匹配产品，不套用固定 AI 模板。
8. 每张图片均可追溯到参考图、提示词、模型和版本。
9. 不合格图片可局部返修，不需要重新执行完整流程。
10. 用户关闭并重新打开页面后，可以从原步骤继续任务。
