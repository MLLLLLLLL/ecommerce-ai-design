# 营销助手2交互式工作流设计文档

## 1. 文档信息

- **文档状态**：方案阶段
- **适用入口**：`/marketing2`
- **设计依据**：`电商主图 & 详情页 AI 全自动化生成工作流.md`
- **设计目标**：把电商主图和详情页的生成过程拆解为可暂停、可确认、可重试的业务工作流。

## 2. 产品目标

营销助手2不是一次性提交表单，而是一个工作流入口中心。用户先选择要执行的功能，再按照步骤完成素材准备、模型处理、人工确认和资产归档。

核心目标：

1. 点击“营销助手2”后先进入工作流卡片中心。
2. 点击卡片进入对应的营销工作流。
3. 文字模型和图片模型全部引用设置中已保存的模型。
4. 当设置中存在多个可用模型时，每个步骤可以独立选择模型。
5. 每个步骤完成后保留结果，用户确认后再进入下一步。
6. 失败步骤可以单独重试，不能影响已经确认的结果。

## 3. 首期工作流卡片

### 3.1 主图 & 详情页全自动生成

完整执行五个阶段，是首期主入口：

```text
素材与参数 -> 底图净化 -> 视觉策划与提示词 -> 分批生图 -> 质检与返修
```

底图净化为可跳过步骤，其余步骤按顺序执行。

### 3.2 产品底图净化

独立处理背景杂乱、光照不均、无关物体和噪点。输出干净产品底图，可直接作为后续工作流的输入。

### 3.3 视觉策划 & 提示词

使用已有产品图、底图和产品参数，生成产品外观锁定描述、主图规划、详情页规划和逐张生图提示词。

### 3.4 分批生图

导入已有提示词或选择历史策划结果，按主图、详情页批次生成图片，并将成功图片写入资源库。

### 3.5 质检验收 & 一键返修

对已有营销图片进行十项检查，并针对外观变形、文字错误、虚构参数和设计质感不足提供单项返修。

## 4. 工作流中心交互

### 4.1 页面布局

- 顶部显示“营销助手2”和最近任务入口。
- 主区域使用响应式卡片网格。
- 桌面端建议 3 列，平板端 2 列，移动端 1 列。
- 每张卡片展示图标、名称、简述、输入要求、输出类型和可用状态。
- 卡片整体可点击，不使用卡片内嵌套卡片。

### 4.2 卡片状态

- **可开始**：依赖条件满足，可创建新任务。
- **需要配置模型**：设置中没有满足能力要求的模型，点击后跳转设置并保留返回路径。
- **继续任务**：存在未完成草稿或等待确认的任务。
- **历史任务**：存在已完成任务，可从历史结果进入后续工作流。

### 4.3 进入规则

点击卡片后进入工作流详情页，并携带 `workflowKey`。直接进入某个中间工作流时：

- 如果已有上游结果，优先提供“从历史结果导入”。
- 如果没有上游结果，显示该工作流所需的最小输入。
- 不自动假设用户拥有产品图、提示词或已生成图片。

## 5. 全自动工作流页面

### 5.1 页面结构

```text
顶部：任务名称、保存状态、返回工作流中心
左侧：五阶段步骤栏
中间：当前阶段表单、预览、结果编辑
右侧：本步骤模型、执行参数、错误和运行记录
底部：保存草稿、执行当前步骤、确认并继续、重试
```

移动端改为上下结构：步骤栏折叠为横向进度条，模型设置和运行记录放在当前步骤下方。

### 5.2 阶段一：素材与参数

表单字段：

- 产品图片：至少 1 张，支持多角度图。
- 平台：淘宝/天猫、京东、抖音、小红书、亚马逊等。
- 输出语言。
- 主图数量、详情页数量。
- 主图比例、详情页比例。
- 产品名称、品牌名、核心卖点。
- 产品参数、目标人群、使用场景、价格带/定位、设计风格。
- 禁止出现、其他要求。

交互规则：

1. 图片上传后先完成服务端校验，再写入任务草稿。
2. 参数为空时显示“待补充参数位”，不得让模型补造数值。
3. 用户可以从资源库选择已有图片，也可以上传新图片。
4. 点击“保存并执行”后进入素材校验结果页。

### 5.3 阶段二：底图净化

- 默认根据图片质量检测结果决定是否推荐执行。
- 展示原图、处理中、净化结果三个状态。
- 支持接受结果、重新生成、跳过。
- 净化模型必须支持图片输入和图片输出或图生图。
- 结果必须保持产品品类、轮廓、比例、结构、颜色、材质、Logo 和包装不变。

### 5.4 阶段三：视觉策划与提示词

拆为两个可观察步骤：

1. **产品视觉识别**：输出外观锁定描述、可见文字、材质、结构、风险和待确认事实。
2. **策划与提示词生成**：输出主图规划、详情页规划、逐张提示词、文字模块和平台限制。

用户可以编辑以下内容后再确认：

- 外观锁定描述。
- 主图/详情页数量。
- 页面职责和顺序。
- 核心卖点。
- 占位参数和禁止内容。
- 单张提示词。

### 5.5 阶段四：分批生图

- 将任务分为主图批次和详情页批次。
- 主图默认 `1:1`，详情页默认 `3:4`，允许在执行前调整。
- 默认逐张提交，提供批量提交开关。
- 显示等待、生成中、成功、失败、已跳过状态。
- 支持单张重试、批次重试和暂停后继续。
- 文件命名遵循：

```text
[产品名]_主图_[序号]_[关键词].png
[产品名]_详情页_[序号]_[关键词].png
```

### 5.6 阶段五：质检与返修

每张图显示十项检查结果：

1. 外观一致性
2. 主体辨识度
3. 信息真实性
4. 版式与文字
5. 详情页决策链
6. 视觉统一性
7. 道具从属性
8. 安全边距
9. 点击转化力
10. 拼接适配度

支持四个固定返修动作：

- 外观变形/跑品修复。
- 文字乱码/错别字修复。
- 虚构参数/夸大功效修复。
- 设计简陋/商业质感增强。

返修前展示将要使用的修复指令，用户确认后创建新的图片子任务，不覆盖原图。

## 6. 每步骤模型选择设计

### 6.1 模型来源

设置页是模型配置唯一维护入口。工作流只读取安全摘要，不允许用户在工作流中输入 API Key、Base URL 或临时模型配置。

### 6.2 选择器规则

- 只展示已启用、属于当前用户、实测通过且能力匹配的模型。
- 选择项显示：配置名称、提供商、模型名称、能力标签和实测状态。
- 提供“使用默认模型”和“跟随上一步模型”选项。
- 每个步骤单独保存选择，不因切换步骤而丢失。
- 模型被删除或停用时，已保存草稿显示失效提示并阻止执行。

### 6.3 能力映射

| 步骤 | 必需能力 |
|---|---|
| 产品识别 | `vision`、`jsonMode` |
| 可见文字识别 | `vision`、`ocr`、`jsonMode` |
| 文案和提示词 | `jsonMode` |
| 底图净化 | 图片输入、图片编辑/图生图 |
| 主图和详情页生成 | 图片生成、参考图输入 |
| 视觉质检 | `vision`、`jsonMode` |
| 图片返修 | 图片编辑/图生图 |

## 7. 任务状态与用户操作

```text
draft
  -> running_step
  -> awaiting_review
  -> running_step
  -> completed

running_step -> partial_failed -> retry / continue
running_step -> failed
```

用户可以：

- 保存草稿。
- 返回上一步修改并重新执行当前步骤。
- 跳过底图净化。
- 重试失败子项。
- 从历史任务继续。
- 导出提示词、质检报告和最终图片。

已确认的上游结果不因下游失败而清空。重新执行产生新版本，不覆盖原始产物。

## 8. 异常与空状态

- 没有可用模型：显示缺少的能力和“前往设置”入口。
- 图片上传失败：保留已成功图片，并显示失败原因。
- 模型能力不足：在执行前拦截，不发起上游调用。
- 上游超时或限流：保留当前步骤输入，允许重试。
- 结果部分失败：成功内容可继续使用，失败项单独处理。
- 用户刷新页面：从任务详情恢复步骤和草稿。

## 9. 验收标准

- 从侧边栏进入后首先看到工作流卡片，而不是空白占位页。
- 每张卡片都能进入对应工作流或给出明确缺失条件。
- 五个阶段有清晰的当前、完成、失败和等待确认状态。
- 每个阶段可以选择设置中的不同模型。
- 模型选择和任务历史可追溯。
- 失败步骤可单独重试，原始结果不被覆盖。
- 1440×900、1024×768、390×844 下无横向溢出和内容遮挡。
- 键盘可以完成卡片选择、步骤切换、模型选择和主要操作。
