# 资源库与画布/工作流互通功能设计文档

## 目标

打通资源库与画布/工作流的双向素材流转：

1. **资源库 → 画布/工作流**：在资源库的资源卡片上直接「加入画布」「加入工作流」，选择目标项目后图片直接进入该项目。
2. **画布/工作流 → 资源库**：在画布编辑器和工作流编辑器内打开资源库选择器，浏览、搜索资源并一键插入当前项目。

本文档只输出设计，不涉及代码修改。

## 现状机制盘点

### 资源库（读取侧已就绪）

- 资源均为图片（`format` ∈ png/jpg/jpeg/webp/gif），`getAssetUrl(asset.filepath)` 转为同源 `/api/files/...` URL（`src/lib/utils.ts:28-32`）。
- 列表接口 `GET /api/assets?page=&pageSize=&search=&source=&folderId=`，支持分页与按提示词/文件名搜索（`src/app/api/assets/route.ts:6-66`）。
- 资源卡片操作区现有 预览/下载/删除 按钮（`src/app/(dashboard)/assets/page.tsx:235-263`），是新按钮的落点。

### 画布消费图片（两条现成通道）

- API 通道：`canvasManager.addImage(url, { left, top })`（`src/lib/canvas/CanvasManager.ts:130-142`），fabric `fromURL` 加载同源 URL 无跨域问题；落图后触发 `object:added` → 历史记录 → 仓库化改造中已接通的 2s 防抖自动保存。
- 队列通道：`useWorkflowBridge.pushToCanvas(url)` 入队，画布编辑器加载完成后（`loading` 门控）`popCanvasImages()` 批量落位（`src/app/(dashboard)/canvas/[id]/page.tsx` 消费 effect）。

### 工作流消费图片（两条现成通道）

- 节点通道：创建 `imageInput` 节点并写 `config.imageUrl`（`src/lib/workflow/nodes/input.ts:52-56`）。
- 队列通道：`useWorkflowBridge.sendToWorkflow(dataUrl)` 写单槽，工作流编辑器加载完成后 `consumeCanvasImage()` 自动创建图片输入节点（`src/app/(dashboard)/workflow/[id]/page.tsx` 消费 effect）。

### 关键结论

两个方向都不需要新建传输机制：仓库化改造留下的「bridge 队列 + 编辑器加载后消费」链路，配合路由跳转，即可实现「直接加入指定项目」；编辑器内加载资源则是一个纯前端的资源选择器组件。

## 功能一：资源库直接加入画布/工作流

### 交互流程

1. 资源卡片操作区新增两个图标按钮：「加入画布」（`Layout` 图标）、「加入工作流」（`Workflow` 图标）。
2. 点击后弹出**目标项目选择对话框**，列出对应仓库的项目卡片（名称 + 缩略图/节点数 + 更新时间，按 `updatedAt desc`），支持按名称搜索。
3. 选择项目后：
   - 加入画布：`pushToCanvas(getAssetUrl(asset.filepath))` → `router.push('/canvas/' + projectId)`；
   - 加入工作流：`sendToWorkflow(getAssetUrl(asset.filepath))` → `router.push('/workflow/' + projectId)`。
4. 编辑器打开并完成项目加载后，现有消费逻辑自动执行：画布图片落位到图层 / 工作流自动创建图片输入节点，toast 提示接收成功，内容随自动保存写回仓库。

### 设计要点

- **为什么是「对话框选项目 + 队列消费」而不是服务端直写 definition**：画布的 fabric JSON 需要在浏览器内由 fabric 实例化（坐标、缩放、序列化都由 fabric 接管），服务端无法可靠合并；队列消费方案下编辑器打开后由 fabric 自己落图，语义正确且零新机制。
- **bridge 结构不改**：`pendingCanvasImages` 队列与 `canvasToWorkflow` 单槽保持原样。对话框负责「选目标」，跳转负责「打开目标」，既有消费逻辑负责「落位」，三段拼出「直接加入」的完整体验。
- **空仓库兜底**：目标项目列表为空时，对话框内提供「新建画布/工作流并加入」按钮（POST 创建 → 同一跳转消费流程）。
- **连续加入**：队列本身支持多张图片（`pendingCanvasImages` 为数组），用户可连续对多张资源执行加入画布，进入项目后一次性全部落位（现有消费逻辑已是批量）。
- 注意插入用 `asset.filepath` 原图，不用 `thumbnail` 缩略图。

### 降级方案（不推荐，仅备档）

不做对话框，按钮只入队 + toast 引导「已进入待接收队列，请到仓库选择项目」，依赖仓库页已有的待接收横幅。体验断点多一步，仅当要压缩本次改动量时采用。

## 功能二：编辑器内加载资源库资源

### 交互流程

1. 画布编辑器、工作流编辑器顶部工具栏各新增「资源库」按钮（`FolderOpen` 图标）。
2. 点击弹出**资源选择对话框**：搜索框（回车触发，复用 `/api/assets` 的 search 参数）+ 图片网格（缩略图 `getAssetUrl(asset.thumbnail || asset.filepath)`，hover 显示文件名/尺寸）+ 底部「加载更多」分页按钮（`pageSize: 24`，`page` 递增累加）。
3. 点击图片插入当前项目：
   - **画布**：计算视口中心的世界坐标（与 `handleAddNode` 同款换算：`(clientWidth/2 - viewport.x) / viewport.k`），`canvasManager.addImage(getAssetUrl(asset.filepath), { left, top })`。落图后 `object:added` → 历史记录 → 自动保存，无需额外处理。
   - **工作流**：`createNode('imageInput', screenToFlowPosition(视口中心))`，`node.data.config.imageUrl = getAssetUrl(asset.filepath)`，`setNodes` 追加。与现有 `consumeCanvasImage` 消费逻辑同模式，自动保存随节点变更触发。
4. 对话框保持打开可连续插入多张，关闭按钮或 Esc 退出。

### 设计要点

- **共享组件**：对话框抽为 `AssetPickerDialog`（受控 `open` / `onOpenChange` / `onSelect(asset)`），取数、搜索、分页全部封装在内部；两个编辑器只提供各自的 `onSelect` 插入逻辑。UI 用现有 `components/ui/dialog.tsx` + `Input` + `Button`，不引新依赖。
- **格式过滤**：仅展示图片格式资源（按 `asset.format` 前端过滤，与资源库卡片同一套格式清单），非图片（如有）不显示。
- **插入位置**：画布用视口中心（与新增节点行为一致）；工作流用 `screenToFlowPosition` 换算的视口中心，退而求其次可固定 `(80, 80)` 偏移。
- **与 bridge 队列互不干扰**：编辑器内直接插入不走队列；队列消费只在项目加载完成后执行一次，两者时序天然隔离。
- **性能**：网格只加载缩略图（`thumbnail` 字段），插入时才取原图；分页累加而非一次性全量。

## 边界情况

- 资源文件已被物理删除但记录仍在：`addImage` / 节点加载失败时 toast 报错（fabric `fromURL` reject 需 catch；`imageInput` 节点执行期由既有 validate 报错）。
- 画布自动保存包含新落图片（fabric JSON 内联图片 URL，体积可控——存的是 `/api/files` 引用而非 dataURL）。
- 工作流执行结果含插入的资源图片时，「送入画布」等既有下游流转不受影响（URL 形态与 `/api/files` 前缀已被 `isImageLike` 覆盖）。

## 验收标准

- 资源库卡片点「加入画布」→ 对话框列出画布仓库项目 → 选择后自动打开该画布编辑器，加载完成后图片落位图层，刷新页面仍在。
- 资源库卡片点「加入工作流」→ 选择项目 → 打开该工作流编辑器，自动创建图片输入节点且 `imageUrl` 已填，节点可正常参与执行。
- 连续对多张图片执行加入画布，进入项目后全部落位。
- 目标仓库为空时，对话框内可一键新建项目并完成加入。
- 画布编辑器内打开资源库对话框，搜索并点击图片后图片出现在视口中心，撤销/重做可用，自动保存生效。
- 工作流编辑器内同样可搜索插入，生成图片输入节点位置在视口中心附近。
- 资源库、仓库页、编辑器的既有功能（预览/下载/删除、保存、导入导出、执行）无回归。
